# SCVK Media — Functional Requirements

## Core requirements
- Dutch-language website.
- Responsive desktop, tablet, and mobile layouts.
- Shared header and footer.
- Navigation labels: **Mijn werk**, **Over mij**, **Freelance**, **Contact**.
- Logo links to the homepage.
- Portfolio overview with useful category filters.
- Individual project pages or suitable external links.
- Responsive embedded video where available.
- A real contact form or a working email alternative.
- LinkedIn and Instagram links using URLs supplied by the owner.
- Essential search-engine optimisation (SEO).
- Documented content-editing process after launch.

## Self-service editing is essential
The owner wants to make changes and add content whenever needed after the website goes live.

The owner should be able to:
- Add, edit, reorder, feature/unfeature, and remove projects.
- Upload and replace thumbnails.
- Add article links, video embeds, and project-detail text.
- Change project categories.
- Edit About-page and freelance-service copy.
- Update contact details and social links.
- Update page titles and meta descriptions where practical.

Prefer a simple content management system (CMS) or visual editing interface if appropriate for the chosen technology and budget. If the site uses code-based content files, explain that editing requires changing files and may require redeploying the site. Do not promise an admin dashboard unless it has actually been built and configured.

Before launch, demonstrate the editing workflow and provide a short guide. Explain who controls the domain, hosting, CMS, backups, access, renewals, and ongoing costs.

## Portfolio filters
- Reflect genuine project categories.
- Provide an **“Alles”** reset option (Dutch for “All”).
- Work on mobile and with a keyboard.
- Clearly indicate the selected filter.
- Do not show empty categories unnecessarily.

## Project pages
- Use stable, readable URLs.
- Include the title, category, image, and owner's role.
- Optional fields should disappear cleanly when no data is available.
- External links must work.
- Never invent dates or publication credits.

## Video
- Use a suitable video-provider embed or secure hosting.
- Provide a responsive player and thumbnail/poster image.
- Do not autoplay audio.
- Include captions/subtitles when available.
- Avoid large video files slowing down the homepage.
- Consider privacy and cookie implications of third-party embeds.

## Contact form
Suggested fields for the Dutch-language form:
- **Naam** — Name (required)
- **E-mailadres** — Email address (required)
- **Onderwerp** — Subject (optional)
- **Bericht** — Message (required)

Additional requirements:
- Accessible labels and validation.
- Clear success and error states.
- A real message-delivery destination.
- Proportionate spam prevention.
- No secrets in client-side code.
- Collect only necessary information.
- Privacy information must match the actual implementation.
- Test message delivery before launch.

## SEO
- Unique Dutch page title and meta description for each public page.
- One meaningful H1 heading per page.
- Descriptive headings and readable URLs.
- Open Graph metadata.
- Sitemap/robots configuration where supported.
- Descriptive image alt text.
- Fast, mobile-friendly pages.
- No fake structured data, fabricated reviews, or keyword stuffing.

## Accessibility and reliability
- Semantic markup and keyboard navigation.
- Visible focus states and sufficient contrast.
- Appropriate image alt text.
- Reduced-motion support.
- No horizontal scrolling at common phone sizes.
- Useful 404 page.
- HTTPS.
- Working contact route and social links.
- Broken-link check before launch.
- Backups and a recovery process explained to the owner.
